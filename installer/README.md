# SentinelOS V.4 [Beta] installer work

This directory contains the Sentinel Package File (SPF) builder and format notes.
SPF files are compressed package containers, similar in purpose to WIM images,
but they are a project-specific format and are **not** Microsoft WIM-compatible.

## Build packages

Run after the normal SentinelOS build has populated the staging trees:

```sh
python3 installer/make_spf.py build \
  --esp-root build/installer/esp \
  --system-root build/installer/system \
  --output-dir installer
python3 installer/make_spf.py verify installer/esp.spf
python3 installer/make_spf.py verify installer/system.spf
```

The ESP staging tree must contain the actual EFI boot files for the installer
media. The system staging tree must contain the installed SentinelOS files.
Do not use the live build/rootfs tree as the ESP tree. No empty or fabricated
boot files are generated by this tool.

## Installer behavior target

* Boot straight to `instlr.exe`; do not launch Winlogon, Explorer, or taskbar.
* Fixed, non-movable window; title text: `SentinelOS V.4 [Beta]`.
* Step 1: terms and conditions.
* Step 2: disk/partition selection. Formatting/removing partitions is disabled
  with a grey overlay until a valid disk/partition is selected.
* Require the explicit `I WANT TO INSTALL THE OS` checkbox before proceeding.
* Then switch to full-screen `screen.exe`, show install progress and the
  bootvid-style spinner.
* Installation target layout: EFI System Partition formatted FAT32; system
  partition formatted ext4.

The SPF builder is implemented and verifies hashes, path safety, archive
membership, and payload integrity. The boot-to-installer path, interactive
installer UI, disk enumeration/partitioning, filesystem formatting, package
application, and ISO mastering still need integration and target-machine tests.
The installer must not format a disk until the user explicitly confirms the
target and the UI displays the destructive action.
